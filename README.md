# G-75 — Онлайн-бронювання + CRM

Повноцінна система для мережі центрів розваг **Лазертаг G-75**: публічний сайт
онлайн-бронювання у стилі референсу + приватна CRM для менеджерів (календар,
ціни, ролі, журнал дій, підтвердження у Telegram).

Стек: **Next.js 14 (App Router) · TypeScript · Prisma · Tailwind**. База даних —
SQLite для розробки (нуль конфігурації), легко перемикається на **PostgreSQL**
для продакшену.

---

## Швидкий старт

```bash
npm install            # встановити залежності (+ prisma generate)
cp .env.example .env    # налаштування (за замовчуванням працює одразу)
npm run db:reset        # створити БД + демо-дані (локації, ціни, броні, акаунти)
npm run dev             # http://localhost:3000
```

- **Сайт бронювання:** `http://localhost:3000/`
- **CRM:** `http://localhost:3000/crm` → вхід `admin@g75.local` / `admin12345`

Демо-акаунти (створює `db:seed`):

| Роль | Email | Пароль | Права |
|------|-------|--------|-------|
| Адміністратор | `admin@g75.local` | `admin12345` | усе: броні, ціни, користувачі |
| Менеджер | `manager@g75.local` | `manager12345` | створює/редагує броні |
| Перегляд | `viewer@g75.local` | `viewer12345` | тільки перегляд |

> ⚠️ Обовʼязково змініть паролі та `AUTH_SECRET` перед запуском у продакшн.

## Що вже зроблено

### Сайт бронювання (публічний, `/`)
- Точний стиль референсу: шапка з логотипом G-75, телефон, **Viber і Telegram**
  окремими кнопками (різні номери — налаштовується в `.env`).
- Три мови: **українська / російська / англійська** (перемикач у шапці, `?lang=`).
- Крок 1: дата, локація, кількість учасників (±), телефон. Автоматичний бейдж
  «вихідний / святковий тариф».
- Вибір розваг (кілька) + **календар вільного часу** по 30-хв сітці на кожну
  розвагу з реальною перевіркою зайнятості з бекенда.
- Тривалість лазертагу **30 / 60 хв** перемикачем (як просив клієнт).
- **Комплексні пропозиції** (Сталкер, Мега-свято) — додаються одним дотиком у
  правильній послідовності свята.
- Додатки (піньяти, аніматор, фотограф, торт, закриття арени…).
- Липкий підсумок з сумою; кнопка «Забронювати» → створює бронь зі статусом
  «Нова» → показує **номер броні + кнопку «Підтвердити у Telegram»** (клієнт
  першим пише в бот через deep-link `?start=CODE`).

### CRM (приватна, `/crm`)
- Захищена middleware (JWT-сесія у httpOnly-cookie). Без входу — редірект на
  логін.
- **Календар** у двох виглядах, як на скрінах клієнта:
  - **Тиждень** — 7 днів × години, картки броней з кольором статусу.
  - **День** — колонки-локації × години, плитки статистики (броні, учасники,
    очікувана виручка, нові/непідтверджені), кнопки «+» для швидкого створення.
- Фільтри: локація (таби) + послуга (список). Легенда статусів
  (Нова/Підтверджена/Аванс/Скасована).
- **Створення броні** вручну (модалка): локація, дата, клієнт, розваги з часом і
  тривалістю, додатки, статус. Ціна рахується за тарифом або вводиться вручну.
- **Редагування броні**: зміна статусу, даних клієнта, **цін кожної позиції**,
  авансу, коментаря; видалення (з підтвердженням).
- **Розваги і ціни** (адмін): редагування цін будні/вихідні по локаціях і
  тривалостях, назв 3 мовами, доступності, розмірів груп, часу на перегрузку.
- **Користувачі** (адмін): створення акаунтів, ролі, скидання паролів,
  активація/деактивація. Захист від блокування власного адмін-доступу.
- **Журнал дій**: хто, коли і що створив / змінив / видалив / змінив ціну — з
  описом. Кожна мутація логується автоматично (`AuditLog`).

### Telegram-підтвердження
- Кнопка на сайті та в CRM веде в бот з `/start <код>` — клієнт починає діалог
  першим (це вимога Telegram, щоб потім йому писати).
- Webhook (`/api/telegram/webhook`) приймає `/start <код>`, привʼязує чат до
  броні (зберігає `telegramChatId` / `@username`) і вітає клієнта.
- Нові заявки з сайту анонсуються менеджерам у чат (`TELEGRAM_MANAGER_CHAT_ID`).
- Потрібно лише створити бот у @BotFather і заповнити змінні в `.env` +
  зареєструвати webhook (див. нижче).

## Реалізовані відповіді на питання клієнта

1. **Месенджери зверху** — так, Viber і Telegram окремими кнопками з різними
   номерами (`NEXT_PUBLIC_VIBER_URL`, `NEXT_PUBLIC_TELEGRAM_URL`).
2. **Три мови** — uk / ru / en.
3. **Ціни/локації з сайту** — закладені як стартові дані, у календарі бронювання
   30/60 хв. Усе редагується в CRM.
4. **Тривалості** — 30/60 хв для лазертагу; для квесту закладено буфер на
   перегрузку `cleanupMin` (за замовч. 15 хв, можна виставити 0 для завантажених
   днів), інші розваги — без буфера.
5. **Графік/свята** — працюємо щодня; святкові дні рахуються за тарифом вихідного
   (`HOLIDAY_MMDD` у `src/lib/catalog.ts`). Години роботи — свої на кожну
   локацію (можна бронювати раніше за домовленістю).
6. **Розваги різні по локаціях** — так, `LocationActivity` визначає, що доступно
   де; у Городку більше розваг і є кімната для шоу (`hasShowRoom`).
7. **Паралельні бронювання** — так; банкетні зали мають місткість = кількість
   кімнат на локації (Нивки 2, Нью-Вей 3, Дрім 1, Городок 7).
8. **Фото розваг** — поле `photo` у моделі `Activity` (готове під завантаження).
9. **Комплекси** — окремі для кожної локації (`Package.locationId`), з реальними
   програмами й цінами з фото клієнта. Клієнт обирає комплекс → перевіряється
   максимум учасників (інакше підказка, де змінити) → показуються лише ті часи
   старту, коли **вся послідовність вміщується** з урахуванням зайнятості
   (квест → лазертаг → паперове шоу → …, банкетний зал паралельно на весь
   період). Обрав час — комплекс бронюється одразу на кілька годин уперед за
   фіксованою ціною.
10. **Передоплата 1000 грн** — показується на сайті, поле `prepaidAmount` у броні,
    статус «Аванс».
11. **Підтвердження** — через Telegram-бот (клієнт пише першим), переписка
    привʼязується до броні в CRM.

## Модель даних (Prisma)

`Location · Activity · LocationActivity · ActivityPrice · Addon · Package ·
PackageItem · Booking · BookingItem · BookingAddon · User · AuditLog`

Ключове у `prisma/schema.prisma`; стартові дані — `src/lib/catalog.ts`.

## Продакшн: PostgreSQL

1. У `prisma/schema.prisma` змінити `provider = "postgresql"`.
2. `DATABASE_URL` → рядок підключення до Postgres.
3. `npx prisma migrate deploy` (або `db push`) + `npm run db:seed`.

## Telegram: підключення бота

```bash
# 1. Створити бот у @BotFather → отримати токен
# 2. Заповнити .env: TELEGRAM_BOT_TOKEN, TELEGRAM_MANAGER_CHAT_ID, TELEGRAM_WEBHOOK_SECRET
# 3. Зареєструвати webhook:
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<ваш-домен>/api/telegram/webhook?secret=<TELEGRAM_WEBHOOK_SECRET>"
```

## Інтеграція з основним сайтом

Кнопка «Забронювати» на `lasertag.in.ua` має вести на цей застосунок
(`/` або `/?lang=ru`). Броні одразу зʼявляються в CRM зі статусом «Нова».

На `lasertag.in.ua/book` сторінку вбудовано в `iframe` з `?embed=1`: тоді
замість повної шапки лишаються тільки «← На сайт» і перемикач мови, а
плаваючі кнопки малює сама сторінка WordPress. Готові блоки для вставки
(рамка з передаванням мови, кнопка в меню, плаваючі телефон/бронювання/
Telegram) — у [docs/WORDPRESS.md](docs/WORDPRESS.md).

Куди веде «На сайт», задають змінні `HOME_URL`, `HOME_URL_RU`,
`HOME_URL_EN` — по одній на мовну версію сайту.
